## 1.0.0：先打通真实 GBA 通信线

**动机。** 目标是在浏览器里保留每位玩家各自的 GBA 核心、画面和输入，通过真实 SIO 通信协作推进，建立用户卡比 ROM 的局域网联机基础。

**实现与影响。** mGBA 编译为 WebAssembly，C 适配层依据 sleep/wake 协作调度推进多个核心。浏览器 Worker 处理模拟与网络；Node 房间服务按座位收集并转发确认输入。页面提供键盘、触屏、标准手柄、画面、音频通路与电池存档。音频接口在本阶段建立，但实际全零 PCM 缺陷直到 1.4.0 才被修复。

**验证边界。** 本阶段独立测试总数没有记录。当前累计回归覆盖 2、3、4 核 SIO 数据交换、确定性、核心运行和电池存档；不能把后续累计结果改写成早期已经完成的完整验证。模拟器能启动或自制 SIO 用例通过，也不能证明真实游戏已完成多人关卡。

**下一步。** 改善输入与房间交流体验，降低重复启动和本机使用的操作成本，形成 1.1.0。

## 1.1.0：完善按键、聊天与桌面启动体验

**动机。** 默认键位不能覆盖不同设备与使用习惯；游戏中需要同房沟通，中文输入法与游戏按键又容易冲突。多次启动服务还需要避免重复占端口。

**实现与影响。** 增加按键重绑、持久化、冲突互换与恢复默认；聊天按房间隔离并保留有界历史，中文输入法组合输入与游戏控制分开处理。启动器识别已有项目服务并复用，其他程序占用端口时寻找可用端口。

**验证边界。** 阶段记录为 25 项自动测试通过；后续浏览器回归继续覆盖重绑、聊天历史、IME、输入隔离及移动布局。这里的房间隔离是消息和状态的业务隔离，不代表房间已有高熵邀请或独立身份授权。

**下一步。** 为少量可信好友的私服使用增加认证和协议边界，同时拆分服务端职责，形成 1.2.0。

## 1.2.0：模块化与 HTTPS/WSS 私服边界

**动机。** 从本机 LAN 走向好友私服，需要明确访问控制、反向代理、资源上限和部署责任；服务端集中在一个入口也不利于继续扩展。

**实现与影响。** 服务端迁入 `src/server/`，分离配置、HTTP、WebSocket、安全及房间逻辑，保留根入口兼容。私服模式引入站点访问口令、会话、注销和 HttpOnly/Secure/SameSite=Strict Cookie，增加精确 Origin/Host 校验、连接和消息限额、超时及安全响应头。Compose、Caddy、systemd 模板说明受控反代与秘密文件挂载方式。

**验证边界。** 阶段记录为 34 项自动测试通过。当前累计验证含本机 HTTPS 反代、双人 WSS、认证拒绝、会话注销和 Compose 离线配置校验；这些证据不证明目标服务器、真实证书签发或公网连通性已验收。共享站点口令不是账号体系，也不是逐房授权；详见 [安全边界](<SECURITY.md>)。

**下一步。** 将单一游戏假设改为显式游戏目录，并隔离不同游戏与不同 ROM 的房间和本地数据，形成 1.3.0。

## 1.3.0：从单一卡比扩展为多游戏目录

**动机。** 增加游戏不应反复修改通用服务器或重新编译模拟器；切换游戏时还必须避免存档、按键及异步导出串用。

**实现与影响。** JSON 目录声明游戏 ID、ROM 相对路径、人数、通信方式及兼容状态，受控下载路由按已启用 ID 查找 ROM。房间固定游戏与人数，加入时匹配游戏。电池存档按游戏及完整 ROM 哈希隔离，按键按游戏隔离，并兼容原卡比数据迁移。准备流程加入存档就绪屏障，所有成员 ready 后才 begin；延迟导出消息保留原游戏、哈希、座位与昵称。

**验证边界。** 阶段记录为 45 项自动测试通过。多游戏浏览器流程以真实卡比和自制 SIO ROM 验证切换、缓存失效、旧档迁移、独立导出、按键隔离和准备屏障；不能外推到所有商业游戏或修改版。

**下一步。** 用用户提供的实际文件建立逐 ROM 验证清单，处理伪装压缩包、单人条目及同底本不同版本，形成 1.4.0。

## 1.4.0：真实 ROM 库、版本指纹与音频修复

**动机。** 文件名或标头代码不足以区分修改版；有的 .gba 实际为压缩包，有的游戏只应开放单人。核心返回样本数也不足以证明实际有声，需要检查 PCM 内容。

**实现与影响。** 导入用户 8 项源文件，加上原卡比得到 9 项运行条目。对改名 ZIP 校验路径、长度、压缩方式、加密标志及 CRC，排除资源文件后提取真实 ROM，原文件保持不变。加入 `link: none` 单人配置、SHA-256 指纹与大小显示、退出房间后切换 ROM 的按钮。两个 BPRE 修改版使用不同 ID、下载路径和哈希空间。

核心修复显式写入 C 结构的实际音量字段 `c->opts.volume`，并重新编译 JS/WASM；原先仅设置配置默认值会使实际音频输出全零。新增 PSG 参考音调及非零 PCM 断言，避免把“返回了样本”当作“声音正常”。

**验证结果。** 2026-11-21 的现有记录列明：

- Windows Node v24.21.0 与 WSL Linux Node v22.22.1 各通过同一组 51 项测试，0 失败、0 跳过；语法与布局检查覆盖 39 个 JS/MJS/CJS 文件。
- 9 个 ROM 的全部声明人数共 23 个基础核心用例通过，另加 6 个延长至 900 帧的音频补测，总计 29/29；九项单人均观测到非零 PCM。
- 同一真实浏览器依次切换九项实际 ROM，各运行超过 360 帧并渲染非纯色画面；两个剑盾版本的 URL 与指纹独立。
- 伪装 ZIP 拒绝路径逃逸、CRC 异常、超限、加密和符号链接等用例。

**尚未证明的内容。** 固定 Start/A 核心探测不识别菜单，不证明串口有效载荷已完成真实玩法交换，也不证明宝可梦交换、对战或四人之剑关卡完成。部分多人短窗口无非零 PCM，延长补测改善了观察范围，但不代表所有人数和启动时刻持续有声。新增条目均维持 `core-tested`，没有把完整玩法标为 verified。

## 当前快照与后续验收

发布准备针对当前 1.4.0 快照；源码、公开 WASM 核心、元数据、测试、部署模板、上游许可与对应源码一起保留。按本次会话用户对私有仓库的明确授权，计划定向加入九项真实运行 ROM 及其目录映射，不重复加入原始 ROM 目录的八项源文件，也不加入伪装 ZIP 原包。默认 ROM 忽略规则仍保留；授权加入文件的具体操作由发布流程完成。此处描述准备范围，不表示已经上传。缓存、真实秘密、存档和测试输出不属于上传范围。

后续工作按以下证据门槛推进：

1. **逐房强邀请与授权。** 设计高熵、可撤销、可过期的邀请或独立房间口令，补齐跨房访问、伪造身份、撤销与过期测试；当前六位房间码和共享站点口令不满足此目标。
2. **真实 ROM 完整玩法验收。** 按每个 ROM 的精确哈希、开放人数和游戏进度，人工验证通信入口、交换、对战、多人关卡、长期运行与存档恢复；区分核心通过和玩法通过，再更新兼容状态。
3. **目标公网环境验收。** 验证镜像完整构建、容器与 secret 权限、Caddy、DNS/ACME、TLS/WSS、跨运营商连通性、实际设备音画触控，以及资源容量与恢复。当前本机反代与模板检查不能替代这些步骤。
4. **同步与扩容设计。** 当前等待确认输入，预测回滚（rollback）、途中热加入、原地断线续传、多实例房间路由和账号体系尚未实现。先建立延迟、抖动、慢设备和确定性基线，再单独设计与验证；不能仅把 Node 副本数增加就宣称支持扩容。
